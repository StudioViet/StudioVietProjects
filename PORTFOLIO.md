## API Reliability Lab: a 60-second review

**The problem:** A timeout can hide a successful write. An unguarded retry can create a duplicate.

**The demonstration:** Send a work order to a deliberately fallible mock provider. Inspect authentication and validation errors, raw 429 responses, bounded retries, safe replay after a lost response, and signed webhook verification.

**The customer-facing skill:** Identify which side failed, preserve the evidence, choose a safe next action, and explain the situation clearly.

[Case study](projects/api-reliability-lab.md) · [Source and setup](career/api-reliability-lab/README.md) · [Validation evidence](career/api-reliability-lab/VALIDATION.md) · [Interview walkthrough](career/api-reliability-lab/WALKTHROUGH.md)
